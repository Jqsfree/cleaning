# 农业（exo_agriculture）清洗评估：机检对齐人工标准的现状与方案

评估日期：2026-08-23
范围：exo_agriculture（农业种植/采摘），以人工标注为 ground truth

## 核心结论

exo_agriculture 是 8 个 exo 品类中清洗链最长、且**唯一已建立「人工标注 → 机检对齐量化」闭环**的品类。三个机检层对齐程度分明：

| 机检层 | 与人工标准的偏差 | 评价 |
|--------|-----------------|------|
| thumb LR 探针 | t_hurt 1.85%、drop 精度 95.12% | ✅ 对齐最好 |
| CLIP v1.1 级联 | t_hurt 5.54%、f_recall 17.86%（旧闸门 0%） | ⚠️ 已起步但漏杀严重 |
| metadata(0.3) | T 误杀率 9.26%，逼近 10% 上限 | ⚠️ 临界风险 |

## 一、清洗链现状（6 层过滤）

| 层 | 实现 | 判定口径 | 阈值 |
|----|------|---------|------|
| 1 文本黑名单 | `cleaner.py` → `core/certain_noise_clean.py`，`rules/blacklist.toml` v0.4.0 | certain-noise 正则 drop（30+ 类串台） | 无数值阈值 |
| 2 文本 LLM QC | `qc/text.py`（qwen） | title+channel 判 T/F/U | U 不自动丢 |
| 3 metadata Stage-1 | `tools/apply_exo_agriculture_metadata_filter.py` → `core/metadata_filter.py` | score<0.3 或 blocklist keyword → reject | **0.3** |
| 4 CLIP 零样本级联 | `run_exo_agriculture_cascade_clip.py` → `cascade_clip.py` | 三键 margin 全过才 pass | q1≥0.0 / q2≥-0.02 / q3≥-0.02 |
| 5 缩略图 VL QC | `qc/vision_thumb.py`（qwen3-vl-flash） | 只 F 确定噪声 | 无数值阈值 |
| 6 thumb LR 探针 | `apply_exo_agriculture_thumb_clip.py` | 高置信 drop only | drop 7.39e-05 / keep 0.0238 |

全链（machine_0814）：quality 2,313,190 → clean 1,828,350 → metadata reject 532,213 → CLIP v1.1 fail 785,051 → thumb LR 最终 keep **261,976**。

## 三、机检 vs 人工偏差量化

### 3.1 CLIP 级联（human678 ∩ embedding store = 411 条）

| 闸门 | clip_fail | T 误伤(t_hurt) | F 召回(f_recall) | drop 精度 |
|------|-----------|---------------|------------------|-----------|
| 旧（q1≥-0.05，require q1+q3） | 0 | 0（0%） | **0%（零过滤）** | — |
| **v1.1 现行**（三键 require） | 40 | 15（5.54%） | 17.86% | 62.5% |

旧闸门对人工 F **完全不过滤**；v1.1 开始有效丢弃，但 F 召回仍偏低（丢不到 1/5 噪声），T 误伤约 1/16。另有 **267 条人标不在 store**（无 CLIP 决策）。

### 3.2 metadata Stage-1（阈值 0.3）

- 全量：1,294,085 候选 → reject 532,213（**省 41.13% CLIP 算力**）
- 实测 T 误杀率 **9.26%**（262 标上），逼近 calibration 上限 **10%**
- 定位：召回优先的省算力闸门，非交付判定，但误杀率已到临界

### 3.3 thumb LR 探针（对齐最好）

- primary(270) OOF：drop 精度 95.12%、t_hurt 1.85%、f_recall 25.32%
- 全量 apply（keep 阈值 0.0238，target 70%）：keep_pass_rate 70.13%、t_hurt 0

## 四、评估结论

**已对齐（人工锚定成立）：**
1. thumb LR 探针：drop 精度 95%、t_hurt 1.85% —— 最可信的自动 drop 层
2. CLIP v1.1：从「零过滤」进步到 f_recall 17.86% —— 已起步但未到位
3. blacklist v0.4.0 锚定 human678，明确 `T_hurt=0`

**未闭合（风险/缺口）：**
1. metadata T 误杀率 9.26% 逼近 10% 上限
2. CLIP f_recall 17.86% 偏低（典型漏杀模式：园艺频道包装、蘑菇/菌类、草坪除草、档案纪实）
3. 267 条人标无 CLIP 决策（不在 embedding store）
4. `ingest_human_qc.py` CLI 缺失（迁移遗漏）
5. exo 仓库无 AGENTS.md（治理表述缺失）
6. calibration 路径漂移（`labels_csv` 仍指向 clean_DATASET）

## 五、对齐方法论（通用模板，供其他品类复用）

1. **产出 gold**：对机检候选帧抽样，人工标 T/F → 归一 `human_label`(pass/fail)
2. **ingest 入库**：`core/human_qc.py` normalize → `03_qc/{labeled,pass,fail,train_export}.csv`，算 `pass_rate`（唯一 KPI）
3. **量化偏差**：在 gold∩机检决策交集上，算 `t_hurt`（误杀）与 `f_leak`（漏杀），产出 disagreement 表
4. **网格校准阈值**：`eval_exo_agriculture_clip.py` 在 gold 上网格搜索，约束「t_hurt≤上限、f_recall 最大化」，写 `calibration.json`
5. **apply 时 halt 闸门**：`--eval-labels` 算 `t_hurt_rate`，超 `max_positive_reject_rate` 即中止
6. **版本化规则 + 模式分析**：blacklist/负例 prompt 记录 `basis`（锚定人标批次）+ 典型 T 误伤/F 漏杀模式，回补规则
